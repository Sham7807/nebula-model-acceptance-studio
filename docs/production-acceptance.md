# 用业务稳定性决定渠道是否接入

能力分回答「本轮协议和功能表现如何」，生产准入回答「证据是否足够支持接入」。两者独立：鉴权异常、必需业务失败或首试错误率超标，不能靠其他检查得分抵消。所有结果仍使用同一 HTML 报告布局。

## 开始一轮有预算的验收

1. 在文本深度检测中选择 Claude、CCMax 或 KVV，填写渠道与模型，选择实际接入协议。
2. 展开「生产接入验证」。Claude 新配置默认快速筛查；CCMax/KVV 默认关闭，可主动开启。旧 API 调用未传 `production` 时保持关闭。
3. 选择负载、持续时间、请求上限、并发和发送速率，再预览请求。生产预算只管附加生产阶段；原生套件、参数矩阵另有请求量。批量选择多个模型会按模型分别执行这些预算。
4. 根据实际接入要求填写成功率、最少样本、观察时窗及延迟条件，必要时填写报价。点击开始后才会调用渠道并产生费用。
5. 完成后先看接入建议、首次成功率、业务分项与分时段表现，再复核具体请求和费用。

| 方案 | 生产阶段时长 | 请求尝试上限 | 并发上限 | 长上下文估算 | 输出上限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 快速筛查 | 2 分钟 | 60 | 2 | 4,096 Token | 2,048 Token |
| 标准验收 | 30 分钟 | 600 | 4 | 12,000 Token | 4,096 Token |
| 持续观察 | 6 小时 | 2,000 | 4 | 16,000 Token | 4,096 Token |
| 自定义 | 最多 24 小时 | 最多 10,000 | 最多 20 | 最多 100,000 Token | 最多 16,384 Token |

请求上限包含基线、鉴权对照、多轮工具每一轮、取消观察和每次重试，不只是任务数。达到请求或估算 Token 预算即停止新增请求；不足的时窗、业务样本或多轮任务保留为证据不足。按持续时间均匀发送或设置每分钟上限；并发上限不是已验证承载能力，报告另列实际峰值。已发出的请求按有限超时收尾，预览显示最大收尾时长。

Token 预算按请求字符量和输出上限估算，不是供应商 tokenizer，也不构成实际扣费硬上限。未设置价格表示未知；明确填写 `0` 才表示零报价。

## 业务覆盖与证据

| 负载 | 实际执行与断言 |
| --- | --- |
| 短请求 | 每任务唯一返回标记，识别空答、错答和串响应 |
| 长输出 / 长流式 | 检查编号、顺序、缺行、末尾标记和协议收尾，记录首个有效内容与内容间隔 |
| 长上下文 | 在文档首、中、尾放置不同标记，要求完整检索 |
| 图像理解 | 内置已知测试图，核对图中方块数，无需另找图片 |
| 推理业务 | 显式请求推理并验证固定计算，推理块是否可观察单独记录 |
| 多轮工具 | 两轮固定 Calculator 调用，再核对最终答案；原样回传 assistant 内容和原生签名，不执行任意模型代码 |
| 取消观察 | 在有效内容到达后关闭客户端连接，单独作为控制证据 |
| 自定义业务 | 同模型、同渠道的 JSON 请求体，要求明确的文本断言，可带图片链接等实际业务内容，禁止覆盖鉴权和传输配置 |

生产阶段支持 Anthropic Messages 和 OpenAI Chat Completions。KVV 官方用例与附加的 Chat 兼容生产请求分别保留证据。通用检测原有 Responses、Gemini 等格式继续可用，但浏览器通用检测不在此生产执行器内；它的报告也显示独立准入结论，缺少生产证据不会被当作正式接入已验证。

真实渠道尚未出现故障时，只能说「本轮未观察到」，不能说已经证明故障恢复。重试仅用于未输出有效内容的有限暂态故障，最多 2 次，遵循退避和 `Retry-After`；不能让重试后成功覆盖首次失败。流式已输出后不自动重放，避免重复交付；工具仅运行固定无外部副作用的计算夹具。关闭客户端连接不能证明上游停止计算或扣费。

## 阅读接入建议

| 建议 | 含义 |
| --- | --- |
| 建议接入 | 本轮配置的准入条件满足，仅限实际已验证范围 |
| 限量试运行 | 已有业务成功证据，但样本、观察或性能条件尚需补齐 |
| 待复测 | 缺少有效基线、鉴权对照或完整生产证据，不能据此判断正式接入 |
| 暂不接入 | 已观察到关键鉴权、业务或稳定性条件异常，先修复再复测 |

默认条件为 99.5% 成功率、至少 200 个正常业务任务、至少 1,800 秒观察，要求短请求、长输出、流式和多轮工具；还检查有效内容首到 P95 与延迟 P95。快速筛查故意达不到完整标准，用于尽早找问题。请按业务要求设定条件，不能为了获得绿色结果随意降低阈值。

报告区分 HTTP 尝试、响应协议完整、首次业务成功、重试后最终业务成功。负向控制不混入正常成功率；多轮工具算一个完整业务任务，其各轮请求单独留存。样本的 95% Wilson 区间也会展示：即使 200 次全成功，也不能证明长期 99.5% SLA；该区间依赖近似独立同分布假设，不能消除集中故障和时段偏差。

能力等级仍按原有模块权重计算。生产证据不足或存在关键风险时，等级标为参考/暂定，并明确接入建议。历史记录重新下载时也遵循这一规则，旧记录不会被补造生产测试结果。

## 按实际请求对账

填写普通输入、输出、缓存读取、缓存写入的每百万 Token 单价和报价版本。Anthropic 的普通输入与缓存输入分开计；OpenAI 的缓存读取是总输入的子集，避免重复相加。累计流式 usage 不逐事件累加。

测试完成后下载账单模板，按本报告分配的请求 ID 填写上游扣费，再上传。模板中的 `amount: null` 表示待填，不表示免费。只填写已经核对的行可以导入部分账单；其余行应移除并保持待核算。未知或重复请求 ID、混币、负数、非有限金额会被拒绝，不做隐式汇率换算。

- 全部测试成本包括原生、矩阵、生产、失败、重试和控制请求。
- 每个生产成功任务成本 = 正常生产任务的全部尝试费用 ÷ 成功完成任务数。失败与重试成本保留，诊断控制单独统计。
- 缺失 usage、报价、请求关联或账单时，不把缺失部分当作零；总额和单成功任务成本可能显示待核算。
- 账单是用户导入的上游扣费证据，工作台不登录供应商账务系统。
- 只有相同币种、协议、业务负载指纹的参考成功任务成本，才可做有条件的成本对比。

账单与准入结论写入验收历史。每个批量模型独立对账，不能用一个模型的低价或高成功率掩盖另一个模型的异常。

## 维护与验证

实现位于 `integrations/channel_production.py`、`channel_admission.py` 和 `report_production.py`。服务请求预览不调用模型；HTML 导出、账单导入和历史回放也不触发模型请求。重启不会自动恢复付费负载，未完成任务保留为中断，需要手动复测。

离线回归覆盖预算、重试、取消、坏协议、业务断言、工具回传、usage 核算、账单归属、鉴权保护及报告证据关联；使用合成传输与临时数据库，不向实际模型付费。

```bash
PYTHONPATH=integrations integrations/.venv/bin/python -m unittest discover -s integrations -p 'test_*.py'
npm test
npm run test:acceptance
npm run build
```

部署后应再用自己允许的请求预算运行真实渠道验收。离线回归证明执行器行为，不代表任何渠道已经通过生产准入。
